The International Phonetic Alphabet (IPA) is the universal standard for documenting human speech, capable of transcribing the sounds of any language on Earth. Yet, if you want to type it today your options are limited. You can use a website with a virtual keyboard to write out letters one click at a time, turning the process of transcription into a slow copy-paste exercise. Or, if you’re a professional linguist, your best bet might be to install Keyman: a complex tool which sits between your OS and your keyboard, designed less for IPA and more for highly complex scripts like Khmer or Tibetan.

As a programmer, the situation has always struck me as absurd. IPA is over 130 years old. It is used by linguists, singers, actors, speech pathologists, news broadcasters — basically anyone who cares about describing and reproducing human speech with scientific precision. Nevertheless, it's still harder to type than languages like Chinese and Japanese, which use complex input method editors (IMEs) to map Latin characters to thousands of logographs.

Armed with Claude, who can both vibe-code a macOS IME and draw on a deep well of knowledge about IPA, phonetics, and orthography, I set out to solve this problem. The result is IPAbet, a fast, intuitive, and native keyboard layout designed specifically for phonetic transcription.

The challenge with building IPAbet had less to do with engineering or technical issues, and more to do with design. The problem is simple: while IPA’s range of symbols is smaller than some world writing systems — officially 107 vowels and consonants, plus around 50 diacritics and other markers — this is still way more than can be represented on the standard ANSI keyboard, which has only 47 keys for letters, numbers, and punctuation.

So where do the other hundred symbols go? The first decision was that the base layer shouldn't change at all. Every unshifted key on an IPAbet keyboard types exactly what it normally types, so email, code, passwords, and terminal sessions all work like they always did. This matters because the alternative is what every special-purpose layout ends up being: a mode you switch into, type three symbols, and switch back out of. If the keyboard is going to be worth leaving on all day, normal typing has to stay normal.

The second decision came from noticing that IPA has no capital letters. There's no uppercase schwa in a transcription, which means the entire Shift layer is available. IPAbet uses it for transformation: typing a capital letter after a symbol transforms that symbol, and the letter you pick corresponds to an actual articulatory feature. <Combo keys="s ⇧H" out="ʃ"/>, and the same ⇧H that turns s into ʃ also turns <Combo keys="t ⇧H" out="θ"/> and relaxes vowels: <Combo keys="i ⇧H" out="ɪ"/>. ⇧R makes a consonant retroflex: <Combo keys="t ⇧R" out="ʈ"/>. ⇧G turns n into <Combo keys="n ⇧G" out="ŋ"/>, which anyone who has learned pinyin will find familiar — a lot of the digraphs were chosen to line up with romanization systems people already know. Two useful properties fall out of this: the mapping works like a small grammar instead of a lookup table, and no symbol ever takes more than two keystrokes.

Diacritics go on the Option layer, and they behave like the Mac's existing dead keys: <Combo keys="⌥n n" out="ñ"/>, the same way it works on the regular US keyboard. Every combining mark on the IPA chart is there, plus the marks you need to type actual languages — the Polish ogonek, the Vietnamese horn, the IAST dots. Deciding which mark deserved which key took longer than writing the input method. At one point I looked at the layer and realized a chunk of it was still occupied by symbols like © and ™, which no one has ever needed in the middle of a transcription. That turned into the working rule for the whole layout: this is a linguist's keyboard, not a lawyer's keyboard. Marks that couldn't justify their key in phonetic terms lost it.

The engine itself is simple, which was also a design goal. There's no composition buffer and no internal state: every keystroke reads the text immediately before the cursor, decides on a single edit, and commits it. This is how Korean input methods work, and it has a nice consequence — the same logic runs as a native macOS input method and as a TypeScript module in the browser. The [scratchpad](/type) and the [typing tutor](/learn) on this site aren't demos of the keyboard; they're the same engine. On Windows and Linux, the browser version already maps the Option layer to AltGr.

Getting the layout right took weeks of going back and forth, mostly between me and Claude, and the process kept producing rules we ended up treating like laws: Shift transforms, Option appends; opening quotes are unshifted; pressing a mark key again cycles through its related family. Some decisions got reversed in ways I didn't expect. We built a "raw mode" toggle so you could switch the whole keyboard off for writing code — then found out macOS refuses to let you remove the plain US layout from your input sources, because password fields need it. In other words the OS already ships a raw mode, with its own indicator in the menu bar, so we deleted ours the same evening. The Catalan l·l lost its spot on the L key and ended up as a double-press on the dot key, which turns out to be a better home for it: <Combo keys="l ⌥. ⌥. l" out="l·l"/>. All of these arguments are preserved in the git history.

There's one non-obvious thing I want to point out, because input methods see every keystroke you type, including the ones that matter. IPAbet is sandboxed with zero network entitlements, which means macOS itself will not let it open a network connection. The privacy claim isn't a line in the README — it's enforced by the OS, and the code is MIT-licensed if you want to verify either half.

IPAbet is out now as version 0.1.0. The low number is deliberate: the layout may still change while early users try it, and I'd rather move keys now than after people have built muscle memory. At 1.0.0 the keystrokes become append-only — Unicode never reassigns a codepoint, and a keyboard layout should make the same kind of promise.

If you want to try it: [the chart](/chart) shows the whole system on one printable page, [/learn](/learn) teaches it to your fingers in an afternoon, and [/type](/type) runs the full engine in your browser with nothing to install. The name of the ǃXóõ language takes six keystrokes, which still delights me.
